Removes the merge friction from the shared files that conflicted in every batch of the v0.25.0 and v0.26.0 releases. Beads: r4q2 (lessons), js2r (decision numbers), plus two filed here, v95z (corpus baseline) and d4es (decisions index). The ingest half is reportsthatmatter/ingest#78 (wwmg). Approach: make the files structurally conflict-free (one file per entry, one item per line, generated index) rather than a git merge driver. A `.gitattributes` `merge=union` line only helps where git's own merge runs; GitHub's merge button does not run custom drivers or read merge attributes as far as GitHub documents (not tested with a throwaway PR), and every agent clone would need it configured. The reasoning is recorded in `docs/design/lessons/README.md`.

## What changed

- **Lessons**: one file per entry, `docs/design/lessons/<YYYY-MM-DD>-<slug>.md` (frontmatter `theme:` plus one line). `pnpm lessons new <slug> --theme "<theme>"` scaffolds, `pnpm lessons` prints by theme, `pnpm lessons themes`, `pnpm lessons check`. `docs/design/lessons.md` is kept as the frozen archive (header rewritten; entries untouched); `tests/lessons.test.ts` fails if it gains or loses an entry.
- **Corpus baseline**: `reports/corpus-baseline.json` split into `reports/corpus-baseline/<id>.json`. `scripts/corpus.mjs` (check, `accept`, `accept <id>`), `tests/density.test.ts`, `scripts/lib/pipeline-status.ts` and its test read the new layout through `scripts/lib/corpus-baseline.ts`. `accept` (all) also deletes files of reports no longer registered.
- **Decisions**: `tests/decisions.test.ts` (via `scripts/lib/decisions.ts`) fails on two records sharing a number, a `# NNNN.` title that disagrees with its file name, or a record with no Status; it is shown failing on a scratch copy with two same-number records. The README index table is gone: it is generated on demand (`pnpm decisions`; also `next` and `check`), so no PR edits a shared table. This replaces the bead's "README has a row for each file" check, which needed the table. Convention (AGENTS.md "Decisions and open questions", agent protocol R12, `0000-template.md`, the README): number the record with the next free number on origin/main when you open the PR, rebase and renumber if main takes it first. R12 used to say "number at merge time"; the bead's rule replaces it. 0020's Beads line now marks oh89 as "(this decision)" so the generated index shows the right bead; no record's content changed.
- Docs and skills that said where to put a lesson, or named `corpus-baseline.json`, updated: AGENTS.md (file table, lessons convention, new "Files that every PR touches are structured not to conflict", "A stacked PR follows its parent"), agent protocol R12 and R14, fix-agent, integrate-and-ship, pr-review, report-pipeline, bead-writing, ingest README, ARCHITECTURE, report-preparation, quality-harness, scoring. Dated design docs are left as history.
