# Agent protocol for the 2026-10-02 session

Layout: `~/src/reportsthatmatter/` holds the site repo `reportsthatmatter/` (shared checkout, main — NEVER switch branches there), `ingest/` (shared checkout of @rtm/ingest, main — never switch branches there either), and one sibling repo per report (e.g. `jack-smith-report/`, `us-deepwater-horizon/`). Beads DB lives in `reportsthatmatter/` (`bd show <id>`, `bd update <id> --notes ...`). Read `reportsthatmatter/AGENTS.md`, `docs/report-pipeline.md` and `scripts/ingest/README.md` before starting. The ingest release, pin-bump and link-override steps are in `scripts/ingest/README.md` under "Changing the library" (AGENTS.md only summarises them under "The pipeline is a pinned dependency").

Several agents run at the same time, each owning different reports. Rules:

1. **Worktrees (also for report repos when another agent may touch the same repo; never edit or switch branches in a shared report checkout if your task shares that repo).** Site: `git -C ~/src/reportsthatmatter/reportsthatmatter worktree add ../rtm-<slug> -b <branch> origin/main`, then `pnpm bootstrap` in it (`CI=true pnpm install` plus `pnpm prerender`; never symlink node_modules). `pnpm corpus check`, `pnpm quality check`, `pnpm typecheck` and `pnpm test` refuse with "Run: pnpm prerender" when `assets/generated/` is missing or older than `reports/*/full.md`, the ingest pin or `scripts/prerender.mjs`; re-run `pnpm prerender` after any of those change (`pnpm setup` is a pnpm built-in, not this). Ingest: `git -C ~/src/reportsthatmatter/ingest worktree add ../ingest-<slug> -b <branch> origin/main`, `CI=true pnpm install`. A report repo is shared by all agents but owned by exactly one agent per session (you are told which): work on a branch there, and put it back on `main` (clean) when you finish, leaving your branch pushed.
2. **Pipeline fixes go in ingest, as passes.** Prefer an opt-in pass the report declares in its `ingest.ts` (like `listedHeadings`, `numberedSections`, `endnotes`) over changing a shared default, so other reports do not move. If you do change a shared default, measure every report's move and say so in your report.
3. **Test against your unreleased ingest** by pointing your site worktree at your ingest worktree (e.g. `pnpm add @rtm/ingest@link:../ingest-<slug>` after `pnpm build` there, or whatever the README describes). Never commit that override.
4. **Do not release.** Do not merge the ingest PR, do not tag, do not merge the site PR, do not deploy, do not publish, do not seed D1. Push branches and open PRs (ingest PR, report-repo PR, site PR as needed; the site PR may temporarily carry the link override ONLY if clearly marked DO-NOT-MERGE — better to leave the pin alone and describe the needed bump). One integrator will release ingest once, bump pins, re-ingest, verify and ship everything in order.
5. **Measure.** Before/after numbers for your defect across the report (and across the corpus if a shared pass). Run `pnpm ingest check` and `pnpm corpus check` and read the diffs for your reports. Never `accept`/`baseline` just to quieten a check — do it because you read the diff. Look at rendered pages (the real product) for the specific examples in the bead.
6. **Peer noise.** Other agents dirty other report repos while you work; if `verify.sh`/corpus check fails ONLY for reports you do not own, check `git -C ../<repo> status` — that is peer noise; note it and move on. Do not edit report repos you do not own.
7. **Editorial.** Paragraph-id moves can break `editorial/<id>.yaml` quotations/ids. If your report's ids move, update its editorial yaml in your site PR (commit only source files; do not commit `src/generated/editorial.ts` — the integrator regenerates it).
8. **Beads.** Update your bead(s) with notes on what you did (`bd update <id> --notes "..."` or `--append-notes`). Do not close them (the integrator closes on ship). File new beads for new defects you find (`bd create ... --deps discovered-from:<id>`); also append a one-line example to `reportsthatmatter-b78.1`'s notes for every defect class you found that no check caught (that bead is collecting examples for a quality-harness epic).
9. **Final report** (your last message): branches + PR URLs (ingest, report repo, site), the passes/options the report's ingest.ts must declare, before/after measurements, every report whose text or ids move, editorial changes, anything unfinished, and any real question for Rufus. Keep it tight.
10. Markdown files: never hard-wrap. Commit messages and PR bodies: plain, no session links needed.
11. Keep going without asking for input; make reasonable decisions and record them.
13b. **Decisions:** questions of direction get a record in docs/decisions/ and a bead labelled decision; never settle them in chat.
12. **Retro (required, last section of your final report).** Under the heading "Getting better faster", answer briefly: what slowed you down; what check, tool or reference text would have caught your defects earlier or let you measure your fix directly; one concrete proposal. The supervisor collects these into the improvement-loop research (reportsthatmatter-38s).
13. **Append to the lessons log.** After your retro, append the lessons worth keeping (one line each, with the bead or doc as evidence, format at the top of the file) to `reportsthatmatter/docs/design/lessons.md` in the same PR as your work. It is the running log the improvement loop (38s) reads; the integrator merges concurrent appends.
